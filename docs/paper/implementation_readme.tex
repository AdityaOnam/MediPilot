% ======================= 1. APPROACH =======================
\section{Implementation Approach}
\label{sec:approach}

The prototype was not built as one application with a model bolted into it. It was built as three
tracks with a deliberate authority gradient between them, because the failure this project exists
to prevent --- a patient deteriorating unobserved in a queue --- is a failure of \emph{who is
allowed to decide what}, not a failure of average accuracy.

\begin{tcolorbox}[mpthesis]
The language model may report. The interface may render. Only the deterministic engine may
decide. No layer may acquire an authority it was not given, and every layer has a non-model
fallback beneath it.
\end{tcolorbox}

\begin{tcolorbox}[mpwarn]
\textbf{All data in this system is synthetic.} No clinical, performance or causal claim is made
anywhere in this repository, and \cm{SIMULATED DATA} belongs on every screen. The metrics quoted
in \S\ref{sec:eval} describe a model trained on a generator, not on patients.
\end{tcolorbox}

Six rules follow, and each is visible in the source tree rather than only in the design documents.

\subsection{1 --- One type contract, mirrored on both sides}
The entire frontend/backend boundary is declared once in \pth{web/lib/api/types.ts} and mirrored
field-for-field by \pth{backend/triage/orchestrator/dto.py}. A field that does not exist in the
DTO cannot reach the nurse board, which makes the contract enforceable by reading two files rather
than by auditing the whole surface.

\subsection{2 --- A tiered fallback ladder, never a single model}
Perception is tiered and the bottom tier is always deterministic. Spoken-answer matching runs
tier~0 (exact bilingual lexicon --- yes/no and 0--10 in English, Devanagari and romanised Hindi),
tier~1 (similarity over labels and synonyms, with an edit-distance rescue for ASR near-misses),
and only then tier~2, where a hosted model is asked to pick one of the option values already on
the patient's screen. Structuring runs local, then hosted, then rule-based. The order is
configuration: \cm{MEDIPILOT\_STRUCTURER} and \cm{MEDIPILOT\_ASR\_BACKEND} each take a
comma-separated preference list whose last entry always works offline.

\subsection{3 --- Clinical behaviour lives in YAML}
Six files under \pth{backend/config/} are the clinical surface, and in a real deployment each
would be separately signed off. Change behaviour there before changing it in Python
(\S\ref{sec:arch}).

\subsection{4 --- The two-clock resource model}
The system does not assume continuous monitoring, because Indian EDs do not have it. Facts decay,
and the decay is explicit: every measurement carries \cm{\{value, takenAt, source, validity\}},
and two clocks run per patient --- re-score (model) and re-measure (physical), on band-specific
cadences from \pth{config/band\_cadence.yaml}.

\subsection{5 --- Offline-first, including the demonstration}
\pth{web/lib/api/adapters/mock.ts} runs the entire twenty-patient corpus in the browser, so all
seven clinical surfaces are demonstrable with no Python process, no credential and no network.
\cm{MEDIPILOT\_INTAKE\_OFFLINE=1} forces every hosted call to behave as though the network were
down --- how the kiosk is rehearsed without burning quota, and how it is demonstrated if venue wifi
fails.

\subsection{6 --- Violations are exceptions, not warnings}
An attempt to lower a band without an attached human action raises
\cm{AsymmetricAutonomyViolation}. Three surge actions --- raising the cost ratio to quieten alarms,
resolving an abstention by guessing, and de-escalating anyone to free capacity --- raise
\cm{SurgeViolation}. These are hard errors on the code path, not lint rules or review conventions.

\begin{tcolorbox}[mpwarn]
\textbf{Two traps in this tree.} A capital-\cm{B} \pth{Backend/} still appears in \cm{ls} on
Windows; it holds nothing tracked, only leftover \cm{\_\_pycache\_\_} and \cm{.pytest\_cache}
shells that the case-insensitive filesystem merges with the real \pth{backend/}. Delete the cruft

(\pth{triage/orchestrator/seed.py}). Moving a single \cm{.py} file to a different depth breaks it
at \emph{runtime}, not at import, so a green collection proves nothing. Move whole subtrees, never
lone files.
\end{tcolorbox}

\section{Technology Stack and Dependencies}
\label{sec:stack}

The system is constrained to commodity hardware on purpose. Nothing on a required path needs a
GPU, a paid cloud tier or a database server --- because the deployment target is a district
hospital, and because DPDP Act 2023 data-locality obligations are easier to honour when the
default path never leaves the building.

\begin{center}\footnotesize\sffamily
\begin{tabular}{@{}p{1.7cm}p{1.9cm}p{3.6cm}@{}}
\toprule
\rowcolor{AccPurple!10}
\textbf{Runtime} & \textbf{Declared} & \textbf{Verified on this machine}\\
\midrule
Node.js & 20+ & v24.16.0\\
\addlinespace[2pt]
Python & 3.10+ & 3.12.3\\
\addlinespace[2pt]
GPU & not required & none present; CPU-only throughout\\
\addlinespace[2pt]
Database & none & state is held in-process\\
\addlinespace[2pt]
Credential & optional & \cm{GROQ\_API\_KEY}, hosted tiers only\\
\bottomrule
\end{tabular}
\end{center}

\subsection{Web (Track B)}
Next.js 16.3.2 on the App Router, React 19.2.8, TypeScript in strict mode, Tailwind v4 through
\cm{@tailwindcss/postcss}, \cm{motion} for animation, and \cm{@react-three/fiber} + \cm{drei} +
\cm{three} 0.185 for the kiosk and mascot scenes. Path alias \cm{@/*} resolves to \pth{web/*}.
Speech capture is the browser's own \cm{webkitSpeechRecognition} plus the Web Audio API --- no
speech dependency is bundled. \textbf{No test runner is wired up on this side}, which is a real gap
rather than an omission from this document.

\subsection{Backend (Track C) --- a deliberate three-file split}
The Python dependencies are split across three files, and the split is a safety boundary rather
than tidiness. Only the first is installed by a deployment.

\begin{itemize}
  \item \pth{requirements.txt} --- the serving path: FastAPI 0.111, Uvicorn 0.29, Pydantic 2.7,
        NumPy 1.26, SciPy 1.13, scikit-learn 1.4.2, PyYAML for the clinical config, joblib for
        artifacts, python-dateutil, pytest 8.2, httpx, plus \cm{groq} and \cm{soundfile} for the
        hosted perception tiers. scikit-learn is pinned exactly: the artifact manifest records the
        version it was trained under, and a mismatch is a silent unpickling hazard.
  \item \pth{requirements-experimental.txt} --- \cm{lightgbm} and \cm{xgboost}, for the GBDT
        bake-off and sequence experiments. Explicitly \emph{not} installed by the API deployment.
  \item \pth{requirements-speech-local.txt} --- the fully local perception path:
        \cm{faster-whisper} 1.1.1, \cm{soundfile}, \cm{silero-vad}, \cm{sounddevice}, with
        \cm{openai-whisper} and \cm{torch} kept only for bake-off comparison. It also carries an
        explicit \cm{requests} pin, because \cm{faster\_whisper/utils.py} imports \cm{requests}
        without declaring it in its own metadata and a clean install otherwise fails at import.
\end{itemize}

\subsection{Perception (Track A)}
One credential, \cm{GROQ\_API\_KEY}, buys both hosted Whisper ASR and the LLM structurer. Two
models, chosen from \pth{docs/benchmarks/structurer\_bakeoff\_table.md}: \cm{gpt-oss-120b} (symptom
F1 0.962, zero red flags missed) for observation extraction, and \cm{gpt-oss-20b} (F1 0.816) for
the cheaper matching and classification calls. A local GPU path was rejected because the
development hardware is AMD --- no CUDA, no ROCm on Windows --- and because the demonstration must
not depend on a live tunnel. Decoding webm/opus for the pre-flight silence gate needs \cm{ffmpeg}
on \cm{PATH}; without it the gate reports itself skipped rather than silently passing.

\subsection{Model}
Gradient-boosted trees over 59 features. The shipped artifact is \cm{medipilot-gbdt-v0.2.0}
(feature version \cm{fx-v4}, 180-minute horizon, scikit-learn 1.4.2), selected by
\pth{model/artifacts/current.txt} and shipped with isotonic calibration, a conformal predictor,
per-stratum thresholds and a \cm{manifest.json}. Four alternates --- xgboost, hist, hist-mono,
last-obs --- sit beside it for the leaderboard.

\section{Solution Architecture}
\label{sec:arch}

\begin{figure*}[p]
  \centering
  % trim strips the blank canvas the export leaves around the drawing
  % (measured content box: 79,79 -> 1212,2205 of 2720x3688, 1px = 1bp at 72dpi)
  \includegraphics[trim=59 1463 1488 59,clip,height=0.87\textheight]{../diagrams/01-full-architecture.png}
  \caption{The six-layer pipeline across three tracks. Track~A (perception) may only report;
  Track~B (interfaces) may only render; Track~C (the risk engine) is the only track permitted to
  assign a band. The dashed returns are the two feedback loops: re-triage every five minutes, and
  overrides plus outcomes becoming training labels.}
  \label{fig:arch}
\end{figure*}

MediPilot is three tracks over two runtimes (Fig.~\ref{fig:arch}). The split is physical: Track~B
is a Node/Next.js payload, Track~C is a Python process, and Track~A is a set of adapters that
either may call but neither may trust.

\subsection{Track B --- the clinical interfaces}
\pth{web/} carries seven clinical surfaces plus a landing page: \pth{/intake} (the patient kiosk),
\pth{/board} (the nurse board), \pth{/card/[id]} (the single-patient card and override panel),
\pth{/hall} (the waiting-hall display), \pth{/counter}, \pth{/control} (demonstration clock and
surge control) and \pth{/audit} (the hash-chained ledger view).
\pth{web/components/clinical/} enforces invariants at runtime rather than by convention ---
\cm{AcuityCard} throws if asked to render a score without a conformal confidence band, and
\cm{LockedAcuitySlot} exists so a human-assigned level has a component that structurally cannot be
lowered by a machine.

\subsection{Track C --- the triage engine}
\pth{backend/triage/} holds the deterministic \cm{band\_engine}, the \cm{surge\_controller}, the
\cm{recheck\_scheduler}, the hash-chained \cm{audit\_log} and the orchestrator.
\pth{backend/rules/} holds the safety floors: \cm{red\_flag\_engine}, \cm{vital\_thresholds},
\cm{spo2\_bias\_guard}. \pth{backend/model/} holds the risk model and its artifacts.

\subsection{Two ASGI applications, not one}
Knowing which app is running matters when reading logs. Both are live, and booting only one and
declaring the backend verified is a mistake that has already been made once here.

\begin{center}\footnotesize\sffamily
\begin{tabular}{@{}p{1.9cm}p{5.9cm}@{}}

\rowcolor{AccPurple!10}
\textbf{App} & \textbf{Module and surface}\\
\midrule
Orchestrator & \cm{triage/orchestrator/app.py} --- \cm{/v1/*}, 20 routes. \textbf{This is what the web app calls.} A lifespan hook bootstraps a \cm{World} and starts a tick loop\\
\addlinespace[2pt]
Risk-model API & \cm{triage/api.py} --- \cm{/score}, \cm{/override}, \cm{/queue}, \cm{/recheck/\{id\}}, \cm{/surge-status}, \cm{/audit/\{id\}}, \cm{/demo/arrival}\\
\bottomrule
\end{tabular}
\end{center}

\vspace{3pt}
\noindent The orchestrator's twenty routes group as: census and state (\cm{/config},
\cm{/census}, \cm{/encounter/\{id\}}, \cm{/stream}); scoring (\cm{/score}, \cm{/decision},
\cm{/rechecks}); intake (\cm{/intake/submit} and five \cm{/intake/tree/*} routes); perception
(\cm{/speech/transcribe}, \cm{/structure}); measurement
(\cm{/encounter/\{id\}/measurement}); surge and audit; and two demo-control routes. Note that
\cm{/override} on the risk-model app is a first-class route rather than an administrative
afterthought --- a human reversal is a normal, recorded event here, not an exception path.

\subsection{Config is the clinical surface}
Six YAML files under \pth{backend/config/} hold behaviour that would otherwise be buried in Python:

\begin{center}\footnotesize\sffamily
\begin{tabular}{@{}p{3.15cm}p{4.65cm}@{}}
\toprule
\rowcolor{AccPurple!10}
\textbf{File} & \textbf{What it governs}\\
\midrule
\cm{age\_strata.yaml} & Six strata with per-stratum normal vital ranges\\
\addlinespace[2pt]
\cm{band\_cadence.yaml} & Re-score and re-measure intervals, wait ceilings, breach actions, per band\\
\addlinespace[2pt]
\cm{red\_flags.yaml} & Observation $\rightarrow$ Red mapping, with per-flag override authority\\
\addlinespace[2pt]
\cm{surge\_policy.yaml} & Detection window, 3$\times$ threshold, what may stretch\\
\addlinespace[2pt]
\cm{label\_spec.yaml} & The training label; frozen and hashed into the manifest\\
\addlinespace[2pt]
\cm{feature\_registry.yaml} & Every field classified \cm{SAFE} / \cm{CONDITIONAL} / \cm{PROHIBITED}\\
\bottomrule
\end{tabular}
\end{center}

\vspace{3pt}
The registry is the enforcement artifact behind the white paper's leakage-lint claim, and it
\textbf{fails closed}: \pth{model/feature\_registry.py} treats any unregistered name as
\cm{PROHIBITED}, so adding a generator field without classifying it breaks the build. That is the
point --- it is how feature drift gets caught mechanically instead of in review.

\subsection{Runtime workflow, end to end}

\textbf{1 · Intake.} Ten steps driven by \pth{web/intake/IntakeApp.tsx}: Welcome $\rightarrow$
Companion $\rightarrow$ HumanOffer $\rightarrow$ Consent $\rightarrow$ Basics $\rightarrow$
Conversation $\rightarrow$ Pain $\rightarrow$ Readback $\rightarrow$ Token, with a HumanLane bail-out
available at any point. \cm{Conversation} walks one of sixteen branches in
\pth{web/intake/tree/branches/} (chestPain, breathing, trauma, obstetric, paeds, poisoning, …).
Branch choice is a local keyword table first; Groq refines it only if the patient has not yet
answered inside the branch. The backend mirrors this for the live path in
\pth{backend/intake/pipeline.py}, which makes \emph{no} clinical decision beyond the deterministic
red-flag table.

\textbf{2 · Scoring.} \pth{backend/model/risk\_model.py} runs a fixed nine-stage pipeline: stratum
resolution $\rightarrow$ vital freshness $\rightarrow$ deterministic red flags (which fire first)
$\rightarrow$ vital thresholds $\rightarrow$ raw risk $\rightarrow$ per-stratum calibration
$\rightarrow$ asymmetric reliability weighting $\rightarrow$ conformal uncertainty $\rightarrow$ a
\cm{ScoreObject} or an \cm{AbstentionObject}, never a partial object. Then
\pth{triage/band\_engine.py} assigns the band, and the SpO\textsubscript{2} bias guard runs before
any de-escalation attempt is even considered.

\textbf{3 · The waiting loop} (Fig.~\ref{fig:lanes}). \pth{triage/recheck\_scheduler.py} re-scores
everyone every five minutes and re-measures on the band cadence; stale readings pull a
re-measurement forward and ceiling breaches escalate. A Green patient who misses two consecutive
rechecks goes Yellow. An abstained patient holds at Yellow and breaches at fifteen minutes
unreviewed. \pth{triage/surge\_controller.py} detects 3$\times$ normal arrival rate and stretches
Yellow 30$\rightarrow$45 and Green 60$\rightarrow$90 minutes. Red never stretches.

\textbf{4 · The human closes it.} Override is one touch from every surface showing a band.
\pth{triage/audit\_log.py} appends a tamper-evident record rendered verbatim on \pth{/audit}, and
consent withdrawal is a new event rather than a deletion. \cm{outcome\_ref} is back-filled later
--- that is the training signal.

\subsection{Degradation, and what the model may not do}
The LLM is confined to Track~A (Fig.~\ref{fig:boundary}). It is a structural parser: unstructured
narrative in, a rigid schema out. It is prohibited from producing an acuity score, assigning a band
or issuing a clinical judgement, and the prohibition is structural rather than advisory --- no
production rule for acuity exists in its output grammar, so the sentence cannot be formed. Tier-2
option matching is the sharpest illustration: the model is handed the options already on the
patient's screen and asked to return one of their values or \cm{NONE}, and anything else it returns
is read as \cm{NONE} on both sides of the wire.

Degradation is symmetrical on the model side. If the artifact is missing, its sklearn version
mismatches, or its feature contract has drifted from the live extractor,
\pth{model/artifact.py} falls back to the frozen AIIMS-ATP rule card and stamps
\cm{score\_source="fallback\_heuristic"}. It does not raise into the triage API. The UI never shows
a blank state.

% ======================= 5. SYNTHETIC DATA =======================
\section{Synthetic Data Generation}
\label{sec:data}

No patient health information exists anywhere in this repository. Everything is manufactured by
\pth{backend/data/generator/}, in four layers, and the design of the label layer is the part worth
reading.

\subsection{Conditions --- joint, not independent, vitals}
\pth{conditions.py} defines clinical archetypes, each with a \emph{correlated joint} distribution
over vitals per age stratum. Vitals are never sampled independently, because independent sampling
mints physiologically impossible patients. Each vital is a truncated normal with hard clipping
bounds.

\subsection{Trajectories --- 37 timesteps per patient}
\pth{trajectories.py} builds a vital-sign trajectory from T=0 to T=180 minutes at 5-minute
intervals, in one of three shapes: \emph{compensating-then-decompensating} (holds, then
deteriorates), \emph{improving}, and \emph{stable-sudden} (stable, then rapid deterioration at a
random inflection point). Seven vitals are tracked --- \cm{hr}, \cm{rr}, \cm{bp\_sys}, \cm{spo2},
\cm{temp\_c}, \cm{gcs}, \cm{pain\_score} --- and each measurement carries the
\cm{(value, timestamp, source, validity)} tuple the freshness model requires.

\subsection{Missingness --- three mechanisms, plus device bias}
\pth{missingness.py} does not apply uniform random dropout, because that is not how data goes
missing in an ED. Three distinct mechanisms are modelled: \emph{sensor failure} (reading present
but flagged invalid), \emph{zero history} (a first-visit patient with no prior records), and
\emph{staff shortage} (reading simply absent, nobody had time). The same module applies a
calibrated upward SpO\textsubscript{2} offset for the darker-skin flag, modelling the occult
hypoxaemia under-detection that the bias guard downstream exists to catch.

\subsection{Labels --- and why they are not circular}
\pth{labels.py} derives the outcome from the per-patient latent, never from the assigned band ---
training on band labels would encode their $\sim$32\% mistriage rate. But the naive alternative,
$\text{label} = f(\text{severity})$, produces a fake result: measured on this generator,
late-window peak severity is essentially a lookup on trajectory shape, and a model trained on it
scores AUROC 0.988 from T=0 vitals alone because it is really doing condition identification.
Three structural choices prevent that:

\begin{enumerate}
  \item \textbf{The label lives strictly in the future.} Features come from steps $\le k$; the
        label is computed over $(k, \text{end}]$. Because the inflection point is per-patient and
        random, the future is genuinely underdetermined by the observation window.
  \item \textbf{A \cm{frailty} latent enters the outcome and never touches any vital.} No feature
        set can recover it, which puts a hard floor under Bayes error.
  \item \textbf{The outcome is a Bernoulli draw, not a threshold.} Two patients with identical
        conditions and near-identical vitals can differ in outcome.
\end{enumerate}

\noindent Together these bound the achievable AUC well below 1.0, and
\cm{severity\_oracle\_auc()} computes that ceiling explicitly so the trained model can be reported
against it rather than against perfection. The primary head is
\cm{critical\_composite\_h180}: the horizon is 180 \emph{minutes}, not 24 hours, and it is named
that way deliberately --- calling it "24h" would be a false claim about what was measured on
synthetic data. \pth{config/label\_spec.yaml} is frozen and hashed into the artifact manifest, so
changing any value there invalidates every trained artifact.

\subsection{Honest stratum coverage}
Five conditions define vitals only for \cm{adult}, and \cm{vitals\_for\_stratum()} silently falls
back to the adult distribution for anything else. Sampling (condition $\times$ stratum) freely
would therefore mint neonates carrying adult trauma physiology, and any per-stratum fairness metric
computed over those rows would be measuring nonsense. Sampling is restricted to explicitly-defined
pairs, and every row records \cm{stratum\_is\_fallback} for audit --- coverage that is narrower and
honest rather than broad and fabricated.

\subsection{The two datasets}
\pth{corpus.py} builds the fixed 20-record demo corpus \cm{P-01…P-20} at seed 42 (\cm{P-01…P-10}
map to the §10 acceptance cases in the brief; \cm{P-11…P-20} add strata and conditions for
generalisation). \pth{bulk.py} builds the N-parameterised training population. The full
generated dataset used for the current models is distributed alongside this document as
\pth{backend/data/train\_set\_100k.zip}. A further \pth{dynamic\_encounters.json} adds fourteen
arrivals that appear over the course of a demonstration, which is why the census returns 34 and
not 20.

% ======================= 6. TRAINING =======================
\section{Model Training}
\label{sec:train}

\pth{model/train.py} runs nine stages and writes a versioned artifact:

\begin{enumerate}
  \item Load the labelled dataset from \pth{bulk.py}
  \item Build features through \pth{model/features.py} --- \emph{the} shared extractor, also used
        at serving time
  \item Split by \cm{patient\_id}, stratified on (stratum, label)
  \item Auxiliary regressor $\rightarrow$ out-of-fold derangement prediction
  \item Primary GBDT classifier
  \item Per-stratum isotonic calibration, on \cm{calib\_iso}
  \item Mondrian split-conformal quantiles, on \cm{calib\_conf}
  \item Cost-ratio thresholds solved on the calibration split
  \item Persist everything plus a manifest
\end{enumerate}

\subsection{Two heads, honestly described}
sklearn has no multi-task GBDT, and lightgbm/xgboost were unavailable while torch was broken in
this environment. So this is a two-stage \emph{stack}, not multi-task learning over a shared trunk:
the auxiliary regressor's out-of-fold prediction becomes one input column to the primary
classifier. That achieves the white paper's "secondary label constrains the primary" effect. It is
not the same architecture, and the code says so in its own docstring.

\subsection{Split discipline}
\cm{calib\_iso} and \cm{calib\_conf} are \textbf{separate splits}. Fitting isotonic regression and
then computing conformal quantiles on the same rows makes those scores in-sample, breaks
exchangeability and voids the coverage guarantee --- while still printing coverage numbers that look
entirely fine. That is the standard way this goes silently wrong, and the separation is the defence.

\subsection{Features}
59 features from \pth{model/features.py}. Per vital, six: the value, a per-stratum $z$-score, the
reading's age in minutes, a slope per hour, a 30-minute delta, and a count of readings. That shape
is what makes deterioration-while-waiting visible to a tabular model at all --- a snapshot model
cannot see a trend.

\subsection{The sequence track}
\pth{model/train\_seq.py} replicates the same calibration, conformal and threshold pipeline over
PyTorch sequence models --- a last-observation baseline, GRU, TCN and Transformer --- reusing
\pth{train.py}'s split and calibration functions directly rather than reimplementing them. This is
the experimental track; it is not what ships.

% ======================= 7. EVALUATION =======================
\section{Evaluation}
\label{sec:eval}

Evaluation is split in two: the risk model (\pth{model/evaluate.py}, \pth{model/leaderboard.py})
and the perception layer (\pth{eval/}). Both report numbers rather than adjectives, and both were
designed to make self-congratulation mechanically detectable.

\subsection{Every metric, three ways}
\pth{model/evaluate.py} reports each headline metric for the trained model, for the hand-coded
baseline it must beat, and for a \emph{severity oracle} that knows the true future peak severity.
The oracle row is the anti-self-congratulation control: a trained model that approaches or exceeds
it has leakage, and that is a mechanical detection rather than a judgement call.

The metric choices follow the white paper rather than convenience. AUPRC is primary, because AUROC
flatters every model at low prevalence. The safety metric is \textbf{under-triage at a fixed
over-triage rate}, not accuracy. ECE uses \emph{quantile} bins, because at $\sim$10\% prevalence
equal-width bins put nearly all mass in bin 0 and ECE collapses to $\approx$0 regardless of real
calibration quality. Fairness is equalised false-negative rate across strata with bootstrap CIs,
never a bare max--min gap, which at these positive counts would be mostly noise.

\subsection{The shipped artifact's committed numbers}
Over $n=4001$ held-out encounters at prevalence 9.8\%:

\begin{tabular}{@{}p{2.9cm}p{1.5cm}p{1.5cm}@{}}
\toprule
\rowcolor{AccPurple!10}
\textbf{} & \textbf{AUROC} & \textbf{AUPRC}\\
\midrule
Trained model & 0.689 & 0.174\\
Hand-coded baseline & 0.630 & 0.156\\
Severity oracle (ceiling) & 0.866 & 0.410\\
\bottomrule
\end{tabular}
\end{center}

\vspace{3pt}
\noindent Conformal coverage is 0.910 overall with a mean set size of 1.08; overall ECE is 0.011;
per-stratum FNR runs from 0.00 (adolescent, $n_{\text{pos}}=35$) to 0.15 (adult,
$n_{\text{pos}}=164$), each with bootstrap CIs and an \cm{underpowered} flag. All eight
\cm{go\_live\_criteria} in \cm{metrics.json} currently evaluate true. Under-triage at a fixed 30\%
over-triage rate is 0.486 --- these are modest numbers on a synthetic task with a deliberate Bayes
floor, and they are reported as they stand.

\subsection{The standing rule for model results}
\pth{model/leaderboard.py} exists to enforce one rule: no model result is reported, discussed or
shipped in isolation. Every model runs through the harness and lands as one row beside the shipped
baseline, the hand-coded rule card, the prevalence floor and the oracle ceiling. \emph{A number
quoted without its row in that table is not a result yet.}

\subsection{Perception bake-offs}
\pth{eval/} answers two questions with numbers. Which Whisper should transcribe the intake
conversation (\pth{run\_asr\_bakeoff.py}, against \pth{asr\_manifest.json}), and which LLM should
extract the structured fields while the perception-only guarantee holds
(\pth{run\_structurer\_bakeoff.py}, against \pth{structurer\_cases.json}, which is deliberately
messy: adversarial, ambiguous, negation, Hinglish, prompt-injection, obstetric, paediatric and
reliability cases). Both import scoring from \pth{eval/metrics.py}, so a number in a notebook and a
number in the report were produced by the same code. Results land in
\pth{docs/benchmarks/}. The structurer table also records \cm{schema\_failures} and
\cm{forbidden\_key\_hits} --- the latter is how the perception-only boundary is measured rather
than assumed.

Both bake-offs run locally against hosted models and on a Kaggle T4 against open-weight ones,
because the development laptop is an AMD Radeon RX 6500M with no CUDA and no ROCm-on-Windows.
\textbf{T4s are Turing and do not support bfloat16}; every notebook uses float16 or 4-bit NF4, and
a model card that says \cm{torch\_dtype=torch.bfloat16} will crash there.

\subsection{The invariant suite}
282 tests collected across \pth{tests/} and \pth{intake/}, covering age stratification (10), the
audit log (6), the band engine (7), corpus acceptance cases (10), features (12), the invariants
themselves (15), model training (11), the orchestrator contract (12), reliability weighting (6),
surge control (8), and the intake pipeline, conversation flow, tree branching, classifier and voice
normalisation (71 across six files).

\section{Scaling: the Target Stack}
\label{sec:scale}

\begin{figure*}[t]
  \centering
  \includegraphics[trim=82 1003 1459 59,clip,width=\textwidth]{../diagrams/04-tech-stack-three-tiers.png}

Everything above describes what runs today: two single-process Python apps and a Next.js payload on
one machine, with all state in memory. That is the right shape for a prototype and the wrong shape
for a hospital. Figure~\ref{fig:stack} is the target, and this section is the honest gap between
them.

\end{tabular}
\end{center}

\vspace{4pt}
Three observations about that table. First, the ordering is not free: \textbf{externalising state
is the prerequisite for every horizontal move}, and attempting workers first produces a system that
looks scaled and silently disagrees with itself. Second, the edge tier is what makes the offline
guarantee real at more than one site --- ONNX plus SQLite plus a PWA is a bench that keeps working
with the network cut, which is the same property the mock adapter gives the demo today. Third, the
federated row is the only one that is a \emph{commitment} rather than an optimisation: raw patient
data never leaves the building, so cross-site learning has to be federated or it does not happen at
all.

None of this is implemented. It is drawn, costed at a target of under Rs.\,5 per encounter in the
white paper, and deliberately not started --- the prototype's job was to establish the clinical
contract, and a distributed system would have made that harder to verify, not easier.

\vspace{4pt}
The distinction matters. The first three are a \emph{packaging} decision --- the training set and
its held-out split are reproducible from a seed, so they are generated rather than committed, and
the tests that consume them cannot run until they are. The fourth is an ordinary stale assertion
left behind when dynamic arrivals were added: true when written, not revisited. Both are stated
here, because a README reporting 278 passing tests while omitting four failures is a README that
has to be re-verified by whoever trusts it.

\subsection{Other known issues, stated plainly}
\begin{itemize}
  \item \cm{npm run lint} \textbf{hangs} with no output and has to be killed. It did this before
        the restructure too. Lint is currently not a usable gate.
  \item \textbf{The orchestrator OpenAPI \emph{baseline} capture is empty} --- 0 paths recorded
        against 20 in the after-state. That before/after comparison did not actually run; do not
        cite it as evidence. The after-state capture is real and is what
        \S\ref{sec:arch} draws on.
  \item \pth{web/README.md} is still stock \cm{create-next-app} boilerplate.
  \item The root \pth{README.md} predates the restructure and still describes the old tree in
        places, including at least one \cm{uvicorn} target that is not a real module path.
  \item Neither Python app is safe to run multi-worker (\S\ref{sec:use}).
  \item The audit-record field count is documented inconsistently elsewhere --- \pth{audit\_log.py}
        says 15, the root README says 16. Counted from the dataclass: 17 substantive fields plus 2
        chain fields.
\end{itemize}

\begin{tcolorbox}[mpbox]
\textbf{What to check before believing a run.} The frontend inlines \cm{NEXT\_PUBLIC\_} variables
at \emph{build} time --- if a change to \pth{.env.local} appears to do nothing, the dev server was
not restarted. The two ASGI apps answer on different route sets, so a 404 on \cm{/v1/census}
usually means \pth{triage/api.py} is running instead of the orchestrator. And a screenshot taken in
mock mode is evidence about the interface only.
\end{tcolorbox}
