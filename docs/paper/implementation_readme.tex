\section{Solution Architecture}
The system enforces a strict boundary between the patient/nurse interfaces and the clinical risk engine.

\subsection{Frontend (Web Layer)}
The frontend (located in \texttt{web/}) is a Next.js 16 application that houses all seven user surfaces, including the interactive kiosk and the nurse board. It manages the talking, branching triage conversation, speech-to-text integration, and local offline phrase matching without performing any clinical evaluation.

\subsection{Backend (Triage Engine)}
The backend (located in \texttt{backend/}) is a Python/FastAPI orchestrator. It contains the deterministic Band Engine, the gradient-boosted Risk Model, and the strict safety floors (Red Flags, SpO2 Bias Guards).

\section{Tech Stack}
The system runs on commodity hardware to comply with the DPDP Act 2023, specifically avoiding mandatory paid cloud GPU dependencies.

\begin{itemize}
    \item \textbf{Frontend:} Next.js 16, React 19, Tailwind CSS 4, \texttt{webkitSpeechRecognition}.
    \item \textbf{Backend:} Python 3.10+, FastAPI, Uvicorn, Scikit-learn, Pandas.
    \item \textbf{Machine Learning:} \texttt{faster-whisper} (CTranslate2, int8), Llama.cpp / Ollama (for offline structural parsing).
\end{itemize}

\section{Role of the LLM}
The Large Language Model (LLM) is strictly confined to \textbf{Track A (Perception Layer)}. 
\begin{itemize}
    \item \textbf{What it does:} The LLM translates unstructured patient narrative into a structured JSON schema (e.g., extracting symptoms and pain levels).
    \item \textbf{What it NEVER does:} The LLM structurally cannot produce an acuity score, assign a triage band, or make clinical judgements. 
\end{itemize}
This extraction falls back to a deterministic, keyword-based structurer if inference resources are constrained.

\section{Production of Synthetic Data}
All data within the repository is entirely synthetic. The 20-record demonstration corpus (located at \texttt{web/lib/seed/corpus.ts} and \texttt{backend/data/corpus\_20.json}) was generated deterministically to test specific edge cases, such as wait-ceiling breaches, out-of-distribution (OOD) gates, and zero-history ABHA paths. No actual Patient Health Information (PHI) was used.
